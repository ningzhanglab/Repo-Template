# Changelog

A concise, user-facing summary of **significant** changes. Follow the spirit of [Keep a Changelog](https://keepachangelog.com/); group related changes rather than recording every commit.

Exact file diffs live in Git history. Use [records/](records/README.md) only when substantial decisions, investigations, experiments, or verification evidence need separate documentation.

**Dates:** collect new entries under `## Unreleased`. When you publish a release or snapshot, rename that section to a dated heading, `## [version] - YYYY-MM-DD` (or `## YYYY-MM-DD` if the project has no version numbers), and start a fresh `## Unreleased` above it. Use ISO dates (YYYY-MM-DD), newest first.

**Authors:** do not name authors or agents in entries; link the PR instead, which records who made and reviewed the change. Thanking outside contributors is welcome. AI involvement belongs in the PR and, for substantial work, in the record's **AI assistance** line.
